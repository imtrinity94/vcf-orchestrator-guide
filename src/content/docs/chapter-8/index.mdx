The first seven chapters built up the tools: the appliance, the canvas, scripting, plug-ins, packages, the API, and the server-side helpers. This chapter uses them for the job most people bring Orchestrator in for, which is automating the private cloud that VCF gives you.

Recipe 8.1 is the base for the rest. It looks at the vSphere plug-in from the inside: the library workflows it ships with, the scripting objects that mirror the vSphere API, how to find one VM quickly in a large inventory, and how to start a vCenter task and wait for it properly. Recipe 8.2 builds on that to clone a VM from a template with a guest customization specification, first with a library workflow and then with a workflow of your own that you can call from anywhere. Recipe 8.3 wraps that workflow in a request that goes to an approver by email, waits for an answer, and builds the VM only when someone says yes.

The rest of the chapter, still to come, turns to the products around Orchestrator in VCF: NSX, VCF Automation's extensibility subscriptions and catalog, and the Orchestrator plug-in for the vSphere Client.

Recipe 8.1 creates and removes snapshots on one test VM. Recipes 8.2 and 8.3 create new VMs in the `vcfguide` folder. Use a cluster and datastore with room for a few small VMs, and delete the VMs when you're done. JavaScript samples are plain ES5.1.

## What changed since vRO 7

The vSphere plug-in is the oldest and most used plug-in Orchestrator has, and the way you script against it has hardly changed. A workflow that clones a VM in vRO 7 reads almost the same in 9.x. What changed is everything around it.
