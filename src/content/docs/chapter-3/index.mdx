This is the heart of Orchestrator. A workflow is a drawing: elements on a canvas, joined by arrows, with data passed between them through named slots. Chapters 1 and 2 got an Orchestrator running and kept it healthy. From here on you build things with it.

The recipes in this chapter build on each other. Recipe 3.1 makes a two-step workflow and explains how data moves through it. Recipe 3.2 adds a reusable action and the canvas moves you need every day. Recipe 3.3 makes the workflow branch, loop, and repeat itself over a list. Recipe 3.4 teaches it to fail well, and recipe 3.5 shows how to pick up a failed run and step through it. Recipe 3.6 gives the workflow a proper run form. Recipes 3.7 and 3.8 make it wait, and run other workflows alongside it. Recipe 3.9, the last, brings people into the run with an approval step.

## The example workflows

Everything you build in this chapter goes in one folder and one action module, so it's easy to find, export, and delete afterwards:

| Object | Name |
|---|---|
| Workflow folder | **VCF Orchestrator Guide/Chapter 3** |
| Action module | `com.vcfguide.chapter3` |

The examples act on the vCenter registered in recipe 1.9, `vc01.vmw.lab`, and only read from it. None of them changes a VM, so you can run them safely against a lab or a production vCenter. Scripts are plain ES5.1 JavaScript, the subset that Orchestrator's Rhino engine handles without surprises: `var` and `function`, with no arrow functions, `let`, `const`, or template strings.
